## El bug de formato source_papers/key_papers — CERRADO DE RAÍZ

Contexto: el 21 mayo se detectó que /ingest producía source_papers en
3 formatos incompatibles. Se corrigió cross-references.md (la tabla de
reglas) — pero NO bastó.

Hoy el paper #11 reincidió en formato inline pese a la doc corregida.
Diagnóstico de causa raíz: SKILL.md L18/L138 ordena explícitamente
"Open runtime-page-templates before drafting frontmatter". Opus copia
el TEMPLATE (ejemplo concreto), no la tabla de reglas abstracta. El
template mostraba `source_papers: []` y `key_papers: []` con corchetes
inline — y Opus replicaba esa sintaxis.

Fix definitivo (commit 3d88e54): runtime-page-templates.en.md y .zh.md
corregidos a formato YAML multilínea con comentario explícito.

VERIFICADO: papers #13, #14 y #17 produjeron source_papers/key_papers
en formato canónico multilínea sin una sola normalización manual. El
bug está cerrado, no parcheado. Documentado en INGEST_AUDIT.md 9.7.

LECCIÓN: cuando una skill ordena "copia este template", el template ES
la fuente de verdad efectiva. Corregir la doc de reglas sin corregir el
template es un fix incompleto.

## Automatización del flujo post-ingest

Creados dos scripts bash (commit f29fb85):

- `scripts/verify_paper.sh` — verificación post-ingest: validator Step 4E,
  lint, formato source_papers multilínea, estado del wiki. No toca git.
- `scripts/commit_paper.sh` — commit + push con salvaguardas: re-corre la
  verificación y aborta si hay 🔴 o validator falla. Modo interactivo pide
  título aparte y cuerpo pegado del resumen de /ingest.

Flujo de trabajo nuevo:
  next_paper.py  →  /ingest  →  verify_paper.sh  →  commit_paper.sh
